# LibreGram Desktop
## Концепция и функциональное описание проекта

> **Статус документа:** черновик концепции. Он фиксирует направление разработки и предварительный набор функций. Детали, помеченные как требующие проверки, не считаются обещанием реализации.

## 1. Краткое описание

**LibreGram Desktop** — самостоятельный настольный Telegram-клиент со своей идентичностью, системой оформления и набором расширенных функций. Проект использует открытую кодовую базу Telegram Desktop и совместимые компоненты других проектов. Главная идея проекта — дать пользователю больше контроля над внешним видом, удобством и локальными возможностями клиента, не ломая совместимость с Telegram и не выдавая локальные функции за серверные возможности Telegram Premium.

LibreGram должен сочетать:

- проверенную основу настольного Telegram-клиента;
- дополнительные функции и подход к настройке, которые можно изучить у AyuGram Desktop и других форков;
- отдельные идеи интерфейса Telegram X, адаптированные под компьютер;
- собственную систему тем и интерфейсной кастомизации;
- удобное управление большим количеством сохранённых аккаунтов;
- необязательную интеграцию локального прокси;
- аккуратный, цельный и современный интерфейс.

**Ключевой принцип:** LibreGram не должен быть случайной коллекцией модов. Все новые функции должны выглядеть и работать как части одного клиента.

## 2. Происхождение и источники идей

### Исходная кодовая база

В качестве технической отправной точки используется открытая C++ / Qt кодовая база Kotatogram Desktop, производная от Telegram Desktop. Это происхождение важно для разработки и соблюдения лицензий, но не определяет пользовательскую идентичность LibreGram. LibreGram развивает собственную концепцию, интерфейс и функциональные модули.

### AyuGram Desktop

Источник идей и отдельных функций для изучения. Перед переносом каждой функции необходимо проверить её актуальность, совместимость с текущей версией кодовой базы, качество реализации и лицензионные условия.

### Telegram X

Источник UX-идей: плавность интерфейса, анимации, переходы, жесты и работа с медиа. Telegram X — Android-приложение, поэтому его код не является прямой основой LibreGram Desktop. Идеи должны быть переосмыслены и реализованы средствами Qt.

### Flowseal / tg-ws-proxy

Отдельный проект для необязательной прокси-интеграции. Его назначение и схема работы должны быть изучены отдельно. Нельзя смешивать его с уже существующей в кодовой базе документацией по прокси-типу `WEB`: это разные механизмы.

## 3. Основные цели

1. Создать удобный настольный клиент на базе проверенной Telegram-кодовой базы.
2. Дать пользователю глубокую настройку внешнего вида без необходимости пересобирать приложение.
3. Добавить локальные функции, которые улучшают повседневное использование.
4. Упростить работу с несколькими аккаунтами и большим количеством сохранённых профилей.
5. Предоставить понятное управление дополнительным прокси-подключением.
6. Сохранять стабильность, безопасность аккаунтов и совместимость с Telegram.

## 4. Функциональные направления

### 4.1. LibreTheme — система оформления

Одна из главных особенностей LibreGram.

Предварительный набор возможностей:

- редактор тем внутри приложения;
- настройка цветов основных областей интерфейса;
- настройка шрифтов, размеров текста и масштаба;
- настройка скруглений, отступов, плотности элементов и размеров панелей;
- фон списка чатов, фон диалогов и отдельные визуальные элементы;
- пользовательские изображения для обоев;
- поддержка анимированных фонов там, где это допускают производительность и используемые компоненты;
- настройка отдельных элементов интерфейса, а не только общей цветовой схемы;
- импорт и экспорт пользовательских тем;
- набор встроенных пресетов.

#### CSS-подобная настройка

Планируется текстовый формат оформления, напоминающий CSS, чтобы продвинутые пользователи могли тонко настраивать интерфейс.

При этом LibreGram работает на Qt, а не в браузере. Поэтому это должен быть собственный безопасный слой стилей с документированными селекторами и свойствами, которые приложение умеет применять. Нельзя обещать полную совместимость с браузерным CSS или произвольное изменение любого элемента без ограничений.

**Требует проектирования:** синтаксис, список поддерживаемых свойств, механизм проверки ошибок, изоляция пользовательских тем и способ их применения без перезапуска.

### 4.2. Local Premium — локальные расширенные функции

Рабочее название набора дополнительных функций клиента.

Под Local Premium подразумеваются исключительно возможности, которые LibreGram может реализовать на стороне приложения: настройки интерфейса, локальные инструменты, дополнительные способы организации чатов и другие удобства.

Это **не**:

- бесплатная активация Telegram Premium;
- обход серверных ограничений Telegram;
- получение платных серверных функций;
- изменение статуса аккаунта на стороне Telegram.

Список конкретных функций Local Premium будет утверждаться отдельно. Каждая функция должна иметь понятное описание, настройку включения и проверку совместимости.

### 4.3. Multi-account — управление аккаунтами и профилями

LibreGram разделяет Telegram-аккаунт и профиль рабочей области.

Telegram-аккаунты внутри одного экземпляра продолжают обслуживаться существующей системой `Main::Domain` и `Storage::Domain`. В исходной кодовой базе есть внутренний лимит 100 аккаунтов для 64-битной сборки и 10 для 32-битной. Увеличивать его до 500 без переработки хранения и сериализации нельзя.

Для цели в 500 сохранённых профилей используется отдельный каталог рабочих областей. Каждый профиль имеет собственную директорию данных и открывается в отдельном экземпляре LibreGram через уже поддерживаемый параметр `-workdir`. Это позволяет не держать все профили загруженными в одном процессе и не менять внутреннюю модель аккаунтов.

**Первый MVP реализован:**

- каталог до 500 сохранённых профилей;
- создание профиля с UUID и отдельной директорией данных;
- хранение метаданных отдельно от авторизационных сессий;
- запуск профиля в отдельном экземпляре LibreGram из существующего меню настроек;
- атомарная запись реестра и проверка его формата.

Новый профиль пустой и при первом запуске требует обычной авторизации. Данные текущего профиля автоматически не копируются. Внутри каждого экземпляра продолжает действовать исходный лимит аккаунтов.

Следующие этапы: группы, метки, избранное, переименование, архивирование, безопасный импорт/экспорт и тесты на 500 записях. Поиск по названию уже доступен в менеджере профилей. 500 сохранённых рабочих областей не означает 500 одновременных подключений.

Безопасность сессий — обязательное условие. Ключи авторизации и API credentials не хранятся в каталоге метаданных, Git или диагностических логах. Подробная схема описана в [MULTI_ACCOUNT.md](MULTI_ACCOUNT.md).

### 4.4. LibreProxy — локальный прокси-модуль

Планируется интеграция с [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy).

Предварительный пользовательский интерфейс:

- включение и отключение модуля;
- запуск вместе с LibreGram по выбору пользователя;
- отображение состояния процесса и локального адреса подключения;
- просмотр диагностических сообщений;
- настройка параметров запуска;
- понятная обработка ошибок и возможность перезапуска.

На первом этапе предпочтительно рассмотреть запуск прокси как отдельного вспомогательного процесса с управлением из LibreGram. Это позволит изолировать его от основного клиента и упростит диагностику.

LibreProxy не является VPN и не гарантирует анонимность, доступность Telegram или увеличение скорости. Поведение и поддерживаемые платформы должны быть проверены до публикации.

**Важно:** существующий механизм/документация прокси-типа `WEB` в унаследованной кодовой базе остаётся отдельной технологией. Решение о взаимодействии между ними будет принято после технического аудита.

### 4.5. UX и повседневное использование

Идеи, которые стоит изучить и адаптировать для настольного интерфейса:

- плавные, ненавязчивые анимации;
- последовательные переходы между разделами;
- улучшенный просмотр фотографий и видео;
- удобные контекстные меню;
- дополнительные настройки списка чатов;
- быстрые действия и сочетания клавиш;
- улучшенная компоновка на разных размерах окна;
- единая система визуальных состояний и обратной связи.

Анимации должны отключаться или уменьшаться настройкой, а производительность должна оставаться приоритетом.

### 4.6. Приватность и контроль

Возможные направления для отдельного проектирования:

- понятные настройки приватности клиента;
- управление локальными данными и кэшем;
- контроль автозапуска и фоновых процессов;
- прозрачное отображение состояния прокси;
- защита локальных настроек и данных аккаунтов;
- безопасные диагностические логи без секретов, содержимого сообщений и ключей.

Функции, влияющие на сетевое поведение или видимость действий аккаунта, должны быть описаны особенно точно и проверены на соответствие Telegram API Terms of Service.

## 5. Интерфейс и визуальное направление

Предварительное направление — современный, аккуратный и настраиваемый интерфейс без визуального шума.

Базовая тема может использовать графитовые оттенки и фиолетовые акценты, но это только стартовый пресет. Пользователь должен иметь возможность заменить палитру и настроить интерфейс через LibreTheme.

Приоритеты дизайна:

- чёткая иерархия элементов;
- спокойные поверхности и контрастный текст;
- единый набор иконок;
- аккуратные состояния наведения, фокуса и нажатия;
- адаптивные размеры панелей;
- отсутствие перегруженных настроек в главных окнах;
- доступность важных функций без длинных цепочек меню.

## 6. Платформы

LibreGram нацелен на две платформы:

1. Linux — основная среда разработки и первичного тестирования.
2. Windows — вторая целевая платформа после проверки базовой функциональности.

macOS исключена из целевых платформ проекта, CI и планов выпуска. Унаследованные платформенные файлы исходной кодовой базы пока сохраняются, чтобы не ломать общие компоненты; они не означают поддержку macOS со стороны LibreGram.

Поддержка Linux или Windows считается подтверждённой только после успешной сборки и тестирования.

## 7. Принципы разработки

- Не переписывать рабочие части Telegram-клиента без необходимости.
- Сначала проверять чистую сборку исходной кодовой базы.
- Разделять новые функции на небольшие независимые изменения.
- Не смешивать интерфейсные функции с сетевым ядром без технической причины.
- Не хранить секреты, API credentials и сессии в Git.
- Не отключать TLS-проверки и другие механизмы безопасности ради обходных решений.
- Учитывать ограничения Telegram API и условия использования.
- Проверять лицензии каждого проекта, из которого берётся код или ресурс.
- Не объявлять функцию готовой до тестирования.
- Сохранять возможность получать и аккуратно интегрировать обновления исходного проекта.

## 8. Что не является целью проекта

LibreGram не должен:

- выдавать локальные функции за официальный Telegram Premium;
- обещать обход серверных ограничений или блокировок;
- позиционировать прокси как VPN или абсолютную анонимность;
- обещать сотни одновременных подключений без подтверждённых тестов;
- внедрять функции ценой потери безопасности и стабильности;
- копировать код из других клиентов без проверки лицензий и совместимости.
