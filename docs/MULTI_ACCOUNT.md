# Multi-account and profile workspaces

**Статус:** каталог профилей, запуск, поиск, сортировка и избранное реализованы; группы и расширенное управление ещё впереди.

## 1. Две разные сущности

В LibreGram важно не смешивать:

- **Аккаунт Telegram** — авторизованная сессия внутри одного экземпляра приложения. Ею управляет существующий `Main::Domain` и `Storage::Domain`.
- **Профиль LibreGram** — отдельная рабочая область приложения со своей директорией данных, настройками, базой и сессиями.

В унаследованном ядре уже есть лимит `Main::Domain::kMaxAccounts`: 100 аккаунтов для 64-битной сборки и 10 для 32-битной. Просто заменить это число на 500 нельзя: индексы аккаунтов участвуют в загрузке и сериализации хранилища.

Поэтому LibreGram не увеличивает этот внутренний лимит. Каталог профилей решает другую задачу: хранит до **500 отдельных рабочих областей**, которые открываются по требованию в отдельных экземплярах приложения.

## 2. Как это устроено

Каждый профиль получает UUID и собственную рабочую директорию. LibreGram запускается с уже поддерживаемым аргументом:

```text
LibreGram -workdir <absolute-profile-directory>
```

Ядро использует рабочую директорию для определения идентификатора одиночного экземпляра. Разные профили поэтому могут открываться независимо, а повторный запуск одного профиля направляется в его существующий экземпляр.

Каталог метаданных хранится отдельно от сессий:

- базовый каталог: `QStandardPaths::GenericDataLocation/LibreGram/`;
- реестр: `profiles.json` (схема 2; схема 1 читается и автоматически обновляется при следующем сохранении);
- директории: `profiles/<uuid>/`;
- внутри каждой рабочей директории приложение самостоятельно создаёт своё `tdata`.

В реестре хранятся только UUID, название, дата создания, время последнего запуска и флаг избранного. API credentials, ключи авторизации и содержимое сессий в нём не хранятся.

## 4. Ограничения текущего MVP

- Новый профиль пустой и при первом запуске требует обычной авторизации Telegram.
- Существующая рабочая область пользователя не перемещается и не копируется автоматически.
- Каждый профиль запускается отдельным процессом LibreGram.
- Внутри одного процесса продолжает действовать существующий лимит аккаунтов.
- Создание, просмотр и запуск реализованы; переименование, архивирование, удаление, импорт и экспорт будут отдельными задачами.
- Группы и пользовательские метки ещё не реализованы; время последнего запуска хранится и используется для сортировки, но пока не отображается отдельной подписью.
- Лимит 500 относится к сохранённым рабочим областям, а не к гарантированному числу одновременно работающих подключений.

## 5. Безопасность и сохранность данных

1. Не копировать авторизационные ключи между профилями автоматически.
2. Не записывать API credentials и данные сессий в `profiles.json`, логи или Git.
3. Реестр защищён файловой блокировкой при изменениях и записывается атомарно.
4. Каталог LibreGram, каталог профилей и новые каталоги профилей создаются с правами владельца.
5. Не удалять профильные директории автоматически при обычном удалении записи из каталога.
6. Перед реализацией удаления добавить явное подтверждение, оценку размера данных и возможность резервного копирования.
7. Не менять текущую рабочую директорию пользователя без отдельного подтверждённого сценария миграции.

## 7. Принцип интерфейса

Менеджер профилей открывается из существующего верхнего меню раздела настроек. Основной экран, список чатов, панель навигации и привычные окна клиента не заменяются.
