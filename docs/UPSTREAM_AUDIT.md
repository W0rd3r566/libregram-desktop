# Аудит исходной кодовой базы LibreGram

**Дата аудита:** 30 октября 2026 года  
**Проверяемая ветка:** `libregram/dev`

Этот документ фиксирует, что уже существует в исходниках до разработки собственных функций LibreGram. Он нужен, чтобы не дублировать готовые механизмы и не ломать привычный интерфейс.

## 1. Состояние репозитория

- Основа проекта — C++ и Qt.
- Текущее дерево содержит около 6,7 тыс. файлов, включая примерно 3,1 тыс. файлов в `Telegram/SourceFiles`.
- Сравнение дерева с `kotatogram/kotatogram-desktop:dev` показало, что исходные файлы и структура кода совпадают; отличия на момент проверки относятся к README и документации LibreGram.
- В исходниках используется версия Telegram Desktop 7.2.9.
- Зависимости и части библиотеки подключаются через Git submodules. Для сборки нужен рекурсивный checkout submodules.
- Проект использует CMake и существующие платформенные workflow для Linux, Windows и macOS.

**Статус сборки:** базовая компиляция в этой среде не запускалась. Совпадение исходников с upstream и корректность конфигурационных файлов не заменяют реальную проверку сборки.

## 2. Что уже есть в исходниках

### 2.1. Темы и оформление

В проекте уже есть нативная система тем Qt:

- `Window::Theme` отвечает за загрузку и применение палитры и фона.
- Существуют редактор темы и предварительный просмотр.
- Поддерживаются файлы тем формата Telegram Desktop и пользовательские фоны.
- Уже есть отдельные ограничения на размер файлов и обработка некорректных данных.

**Вывод для LibreTheme:** не заменять систему тем новой самописной реализацией. Развивать её как совместимый слой пользовательских пресетов и дополнительных параметров поверх `Window::Theme`. CSS-подобный синтаксис должен быть собственным ограниченным форматом, а не обещанием полноценного браузерного CSS.

### 2.2. Локальные настройки Kotatogram

В коде есть `Kotato::JsonSettings`:

- настройки хранятся отдельно от настроек Telegram-сервера;
- предусмотрены глобальная и аккаунтная области;
- поддерживаются типы bool, int, string и JSON array;
- для значений есть обработчики проверки и ограничения;
- предусмотрены события изменения, отложенная запись и настройки, применяемые после перезапуска;
- пользовательский JSON хранится в `tdata/kotato-settings-custom.json`.

**Вывод для LibreGram:** использовать существующую инфраструктуру там, где она подходит. Новые параметры LibreGram следует отделять собственным префиксом/пространством имён и постепенно отвязывать пользовательскую документацию от внутренних названий исходного проекта. Не создавать второй конкурирующий файл настроек без технической необходимости.

### 2.3. Несколько аккаунтов

В текущем коде уже есть:

- `Main::Domain` и `Main::Account` для управления аккаунтами;
- сохранение и загрузка аккаунтов через `Storage::Domain`;
- переключение активной сессии;
- обработка лимита аккаунтов в логике загрузки хранилища.

Проверенные ограничения исходной реализации:

- до 100 аккаунтов для 64-битной сборки;
- до 10 аккаунтов для 32-битной сборки.

Это ограничение количества аккаунтов в текущем ядре, а не готовая реализация каталога из 500 сохранённых профилей.

**Вывод для LibreGram:** целевые 500 профилей проектировать как отдельный каталог сохранённых профилей с ленивой активацией. Не подменять это увеличением `kMaxAccounts`: активные сессии потребляют память и ресурсы, а индексы аккаунтов участвуют в сериализации и хранении.

### 2.4. Прокси

В ядре уже есть управление стандартными типами прокси:

- SOCKS5;
- HTTP;
- MTProto;
- WEB.

Также существуют проверка прокси, список прокси и механизм ротации.

**Вывод для LibreProxy:** интеграция с Flowseal/tg-ws-proxy остаётся отдельным необязательным локальным сервисом. Не смешивать его с существующими типами прокси Telegram Desktop, не менять автоматически системный маршрут и не переименовывать существующий WEB proxy.

### 2.5. Базовый интерфейс

Основные экраны, контролы, стили, окна и поведение диалогов уже реализованы на Qt. Не требуется строить отдельный фронтенд.

**Правило разработки:** не делать редизайн и не заменять существующие окна. Новые настройки и действия добавлять только в подходящие существующие места, используя принятые в исходниках компоненты, размеры, типографику, анимации и паттерны. UX-идеи Telegram X адаптировать под desktop, а не переносить Android-код напрямую.

## 3. Внешние источники

| Проект | Что изучать | Что не делать |
|---|---|---|
| Telegram Desktop / Kotatogram Desktop | Совместимость ядра, Qt-компоненты, существующие механизмы | Не копировать исходники заново поверх текущей базы |
| Telegram X | Жесты, переходы, плавность, поведение медиа и навигации | Не переносить Java/Android-код в C++/Qt |
| AyuGram Desktop | Отдельные локальные функции после аудита реализации и лицензии | Не переносить функции вслепую |
| Flowseal/tg-ws-proxy | Возможности локального helper-процесса и его протокол управления | Не считать его VPN или заменой всем прокси Telegram |

## 5. Следующий порядок работ

1. Проверить чистую сборку исходного проекта с рекурсивными submodules на Linux.
2. Проверить, что приложение запускается и сохраняет прежние экраны и пользовательские данные.
3. Проверить Windows и macOS metadata/build конфигурации.
4. Выделить настройки LibreGram в собственное пространство имён поверх существующего механизма настроек.
5. Реализовывать LibreTheme небольшими совместимыми этапами.
6. Спроектировать каталог сохранённых аккаунтов отдельно от активных сессий.
7. Добавлять LibreProxy отдельным opt-in helper-процессом.
8. После каждого этапа проводить сборку, регрессионную проверку и проверку хранения данных.
